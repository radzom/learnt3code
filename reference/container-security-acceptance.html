Container-Sicherheitsabnahme

Eine Konfiguration ist erst akzeptiert, wenn erlaubte Arbeit funktioniert und verbotene Zugriffe nachweislich scheitern.

Unverhandelbare Grenzen

  • Kein Mount von Host-Root, Host-Home oder ~/.ssh.
  • Kein Mount von /var/run/docker.sock.
  • Kein privileged-Modus und keine unnötigen Linux-Capabilities.
  • Schreibbare Bereiche werden einzeln benannt: Workspace, T3-Zustand, Agent-Zustand und temporärer Speicher.

Abnahmeregel

Ein einziger erfolgreicher verbotener Zugriff stoppt die Abnahme. Erst Ursache beheben, Container neu erstellen und die gesamte Matrix erneut ausführen.

Quellen: T3-Ausführungsgrenze, Docker Container Security, Docker Engine Security.

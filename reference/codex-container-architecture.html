T3 Code + Codex im Container

T3-Client→T3-Server→Codex CLI

Der Client bleibt auf dem Host. T3-Server und Codex CLI teilen dieselbe gehärtete Containergrenze, weil der T3-Server Agentenprozesse, Terminal, Git und Dateisystemoperationen ausführt.

Netzwerkgrenze

Host-Port 3774 wird nur an 127.0.0.1 veröffentlicht und auf Port 3773 im Container weitergeleitet. Damit kollidiert das Profil nicht mit dem lokalen Backend der T3-Code-Desktop-App auf Host-Port 3773. Der Container nutzt ein gewöhnliches Bridge-Netzwerk statt des Host-Netzwerks. Ausgehender Netzwerkzugriff bleibt zunächst erlaubt, weil Codex den OpenAI-Dienst erreichen muss; eine Egress-Allowlist ist eine spätere Härtungsstufe.

Prozesshärtung

  • Nicht-root-Benutzer mit UID 10001.
  • Nur lesbares Root-Dateisystem.
  • Alle Linux-Capabilities entfernt.
  • no-new-privileges aktiviert.
  • Kein Docker-Socket und kein Host-Netzwerk.
